1. 파일 구성
--------------------------------------------------------------------------------
  counter_app.py          프로그램 소스 (화면 / 장비 통신)
  storage.py              프로그램 소스 (환경설정 읽기 / CSV·DB 저장)
  counter_app.spec        PyInstaller 빌드 설정
  USB_serial_check.py     연결된 COM 포트 / USB 시리얼 번호 확인용 도구
  modbus_check.py         카운터 레지스터 값 확인용 도구 (현재값 주소/워드 순서 확인) → 6-5
  dist\counter_app.exe    빌드된 실행 파일 (서버에는 이 파일만 복사하면 됨)

  프로그램 실행 후 exe와 같은 폴더에 자동 생성되는 파일
  settings.ini                            환경설정 (저장 방식 CSV/DB, DB 접속 정보 등) → 6장
  counter_config.json                     카드 목록 / 포트 / 자동 연결 여부 (자동 관리)
  counter_log_<장비명>_<날짜>.csv          카운트 기록 (CSV 저장 시, 날짜별 파일)
  counter_data.db                         카운트 기록 (DB 종류가 sqlite 일 때)
  db_pending.csv                          DB 연결이 끊긴 동안 쌓인 미전송 데이터
                                          (DB 가 다시 연결되면 자동 전송 후 삭제됨)


--------------------------------------------------------------------------------
2. 개발 PC에서 실행하기 (Python)
--------------------------------------------------------------------------------
  (1) 필요한 패키지 설치 (명령 프롬프트)

      pip install PyQt5 pymodbus pyserial

      DB 에 저장하려면 사용할 DB 의 드라이버를 추가로 설치합니다. (sqlite 는 필요 없음)

      MySQL / MariaDB :  pip install pymysql cryptography
      MS-SQL Server   :  pip install pyodbc
      PostgreSQL      :  pip install psycopg2-binary

  (2) 실행

      python counter_app.py


--------------------------------------------------------------------------------
3. 실행 파일(exe) 만들기
--------------------------------------------------------------------------------
  ※ 소스(counter_app.py)를 수정했다면 반드시 다시 빌드해야 exe에 반영됩니다.

  ※ DB 저장을 사용할 경우, 빌드하기 전에 해당 DB 드라이버가 설치되어 있어야
     exe 에 포함됩니다. (2장 (1) 참고. 여러 개 설치해 두면 모두 포함됨)
     드라이버 없이 빌드한 exe 에서 DB 를 선택하면 하단에
     "DB 드라이버가 설치되어 있지 않습니다" 오류가 표시됩니다.

  (1) PyInstaller 설치 (최초 1회)

      pip install pyinstaller

  (2) 빌드 (counter_app.py가 있는 폴더에서 실행. storage.py 는 자동으로 함께 포함됨)

      python -m PyInstaller --noconsole --onefile counter_app.py

  (3) 결과물: dist\counter_app.exe

4. 서버 PC에 설치하기
--------------------------------------------------------------------------------
  (1) 프로그램 폴더 만들기
      예) C:\CounterApp\

      ※ "C:\Program Files" 아래에는 두지 마세요.
         쓰기 권한이 없어 설정 파일과 CSV 로그가 저장되지 않습니다.

  (2) dist\counter_app.exe 를 C:\CounterApp\ 에 복사
      - 처음 실행하면 같은 폴더에 settings.ini 가 자동으로 만들어집니다.
        기본값은 CSV 저장이며, DB 저장은 6장을 참고해 설정합니다.

  (3) USB-시리얼 변환기(SCM-US48I) 드라이버 설치 후 장비 연결
      - 장치 관리자 > 포트(COM & LPT) 에서 COM 번호 확인
      - 여러 대일 때는 USB_serial_check.py 로 시리얼 번호를 확인한 뒤
        counter_app.py 의 DEVICE_MAP 에 등록하면 포트 목록에 장비 이름이 표시됩니다.

  (4) counter_app.exe 실행 → 카드마다 이름/포트 지정 → [▶ 연결 시작]
      - 연결에 성공한 카드는 설정 파일에 "자동 연결"로 기록되어,
        다음 실행(재부팅 포함) 때 자동으로 다시 연결됩니다.
      - [■ 연결 끊기]를 누른 카드는 다음 실행 때 자동 연결하지 않습니다.

  (5) COM 포트 번호 고정 (권장)
      USB를 다른 포트에 꽂으면 COM 번호가 바뀌어 자동 연결이 실패합니다.
      - 장비는 항상 같은 USB 포트에 꽂아 두세요.
      - 필요하면 장치 관리자 > 해당 COM 포트 > 속성 > 포트 설정 > 고급
        > "COM 포트 번호"에서 번호를 직접 지정할 수 있습니다.

5. 부팅 시 자동 실행 설정
--------------------------------------------------------------------------------
  이 프로그램은 화면(창)이 있는 프로그램이므로 "Windows에 로그인된 상태"에서
  실행되어야 합니다. 따라서 [5-1 사전 설정]으로 자동 로그인을 켠 뒤,
  [5-2 방법 A] 또는 [5-3 방법 B] 중 "하나만" 설정하세요.
  (두 가지를 모두 설정하면 프로그램이 2개 실행되어 COM 포트 충돌이 납니다.)

  권장: 방법 B (작업 스케줄러) - USB 장치 인식을 기다리는 지연 실행이 가능


  ---------------------------------------------------------
  5-1. 사전 설정 (서버 PC에서 1회)
  ---------------------------------------------------------
  (1) Windows 자동 로그인
      a. Win + R → netplwiz 입력 → 확인
      b. 프로그램을 실행할 사용자 선택
      c. "사용자 이름과 암호를 입력해야 이 컴퓨터를 사용할 수 있음" 체크 해제
      d. 확인 → 해당 계정 암호 입력

      ※ 체크박스가 보이지 않으면 (Windows 10/11):
         설정 > 계정 > 로그인 옵션 >
         "보안 향상을 위해 ... Windows Hello 로그인만 허용" 을 끔 → 다시 netplwiz 실행
      ※ 또는 Microsoft 공식 도구 "Autologon" (Sysinternals) 을 사용해도 됩니다.
      ※ 자동 로그인은 누구나 PC를 사용할 수 있게 되므로,
         프로그램 실행 전용 로컬 계정을 만들어 사용하는 것을 권장합니다.
         (로그인 후 Win + L 로 화면을 잠가도 프로그램은 계속 동작합니다.)

  (2) 절전 모드 끄기 (관리자 권한 명령 프롬프트)

      powercfg /change standby-timeout-ac 0
      powercfg /change hibernate-timeout-ac 0

      ※ 모니터 끄기는 상관없습니다. "절전(대기)"만 꺼져 있으면 됩니다.

  (3) USB 절전 끄기 (USB-시리얼 연결이 끊기는 것 방지)
      a. 제어판 > 전원 옵션 > 설정 변경 > 고급 전원 관리 옵션 설정 변경
         > USB 설정 > USB 선택적 절전 모드 설정 → "사용 안 함"
      b. 장치 관리자 > 범용 직렬 버스 컨트롤러 > 각 "USB 루트 허브" > 속성
         > 전원 관리 탭 > "전원을 절약하기 위해 컴퓨터가 이 장치를 끌 수 있음" 체크 해제

  (4) (선택) 정전 후 자동 켜짐
      BIOS 설정에서 "Restore on AC Power Loss" (또는 AC Power Recovery)
      항목을 "Power On" 으로 설정하면 정전 복구 시 PC가 자동으로 켜집니다.
      (메뉴 이름은 메인보드 제조사마다 다릅니다.)

  (5) (선택) Windows 업데이트 자동 재시작 시간 조정
      설정 > Windows 업데이트 > 고급 옵션 > 사용 시간 에서
      라인 가동 시간대를 사용 시간으로 지정해 두면 가동 중 재시작을 줄일 수 있습니다.
      (재시작되더라도 자동 로그인 + 자동 실행으로 수집이 다시 시작됩니다.)


  ---------------------------------------------------------
  5-2. 방법 A - 시작프로그램 폴더 (가장 간단)
  ---------------------------------------------------------
  a. C:\CounterApp\counter_app.exe 를 마우스 오른쪽 클릭 → "바로 가기 만들기"
  b. Win + R → shell:startup 입력 → 확인  (시작프로그램 폴더가 열림)
  c. 만든 바로 가기를 이 폴더로 이동
  d. 재부팅하여 로그인 후 프로그램이 자동으로 뜨는지 확인

  해제: shell:startup 폴더에서 바로 가기 삭제

  ※ 로그인 직후 바로 실행되므로, USB 장치 인식이 늦으면 "연결 실패"가 뜰 수 있습니다.
     이런 경우 [▶ 연결 시작]을 누르거나 방법 B 를 사용하세요.


  ---------------------------------------------------------
  5-3. 방법 B - 작업 스케줄러 (권장)
  ---------------------------------------------------------
  [화면에서 설정하기]
  a. Win + R → taskschd.msc 입력 → 확인
  b. 오른쪽 "작업 만들기..." 클릭 ("기본 작업 만들기" 아님)

  c. [일반] 탭
     - 이름: 카운터 모니터링
     - "사용자가 로그온할 때만 실행" 선택
       (※ "로그온 여부에 관계없이 실행"을 고르면 창이 화면에 보이지 않습니다)

  d. [트리거] 탭 → 새로 만들기
     - 작업 시작: "로그온할 때"
     - 특정 사용자: 자동 로그인하는 계정
     - 고급 설정 > "작업 지연 시간" 체크 → 30초
       (USB-시리얼 장치가 인식될 시간을 줌. 연결 실패가 잦으면 1분으로)

  e. [동작] 탭 → 새로 만들기
     - 동작: 프로그램 시작
     - 프로그램/스크립트: C:\CounterApp\counter_app.exe
     - 시작 위치(옵션):   C:\CounterApp

  f. [조건] 탭
     - "컴퓨터의 AC 전원이 켜져 있는 경우에만 작업 시작" 체크 해제 (노트북인 경우)

  g. [설정] 탭  ← 중요
     - "다음 시간 이상 작업이 실행되면 중지" 체크 해제
       (기본값 3일 → 체크되어 있으면 3일 뒤 프로그램이 강제 종료됩니다!)
     - "작업이 이미 실행 중이면 적용되는 규칙": "새 인스턴스 시작 안 함"

  h. 확인 → 재부팅하여 로그인 30초 후 프로그램이 뜨는지 확인

  [PowerShell 로 한 번에 설정하기] (위 a~h 와 동일한 내용)
  자동 로그인 계정으로 로그인한 상태에서 "관리자 권한 PowerShell"을 열고
  아래 내용을 붙여 넣으세요. (exe 경로가 다르면 첫 줄만 수정)

      $exe = "C:\CounterApp\counter_app.exe"
      $action    = New-ScheduledTaskAction -Execute $exe -WorkingDirectory (Split-Path $exe)
      $trigger   = New-ScheduledTaskTrigger -AtLogOn -User "$env:USERDOMAIN\$env:USERNAME"
      $trigger.Delay = "PT30S"
      $principal = New-ScheduledTaskPrincipal -UserId "$env:USERDOMAIN\$env:USERNAME" -LogonType Interactive -RunLevel Limited
      $settings  = New-ScheduledTaskSettingsSet -ExecutionTimeLimit ([TimeSpan]::Zero) -MultipleInstances IgnoreNew -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries
      Register-ScheduledTask -TaskName "CounterMonitor" -Action $action -Trigger $trigger -Principal $principal -Settings $settings

  바로 실행해 보기:  Start-ScheduledTask -TaskName "CounterMonitor"
  해제:              Unregister-ScheduledTask -TaskName "CounterMonitor" -Confirm:$false

6. 저장 방식 설정 (CSV / DB) - settings.ini
--------------------------------------------------------------------------------
  exe 와 같은 폴더의 settings.ini 에서 설정합니다.
  (프로그램 상단 [⚙ 환경설정] 버튼을 누르면 메모장으로 열립니다)
  ※ 수정 후에는 프로그램을 "다시 시작"해야 적용됩니다.
  ※ 파일을 지우면 다음 실행 때 기본값으로 다시 만들어집니다.
  ※ 프로그램을 새 버전으로 교체하면, 기존 settings.ini 에 없는 새 설정 항목이
     실행 시 기본값과 설명으로 자동 추가됩니다. (기존에 수정한 값은 그대로 유지)
     추가된 항목은 "; ↓ 새 버전에서 추가된 설정 (자동 추가됨)" 표시 아래에 있습니다.
  ※ settings.ini 는 GitHub(소스)에는 포함되지 않습니다. exe 폴더에 실행 시 생성되는 파일입니다.

  ---------------------------------------------------------
  6-1. 주요 항목
  ---------------------------------------------------------
  [general]
    station          이 PC(설비)를 구분하는 이름. 비우면 컴퓨터 이름 사용.
                     여러 PC 의 데이터를 서버 DB 한 곳에 모을 때 PC 구분용으로 저장됨.
                     예) station = 1공장-A라인
    poll_interval_ms 값 읽기(=화면 갱신) 주기. 1000 = 1초

  [modbus]  (카운터 통신 - CT 시리즈 기본값으로 설정되어 있음)
    baudrate / parity / stopbits / slave_id
                     통신 속도 / 패리티(E,O,N) / 정지 비트 / 국번. 카운터 통신 설정과 같아야 함
                     기본: 9600 / E / 1 / 1
    register_type    현재값(PV) 레지스터 종류: input(기능코드 04) / holding(기능코드 03)
    pv_address       현재값 레지스터 주소 (0 부터). 매뉴얼 주소 301004 → 1003
    word_order       32비트 값의 워드 순서: low_first (CT 시리즈) / high_first
    reset_coil_address [0 리셋] 버튼이 ON 을 보낼 Coil 주소 (0 부터)
    ※ 기본값: Input Register 1003 (301004), low_first
       화면에 터무니없는 숫자(음수, 수십억 등)가 나오면 이 항목들을 6-5 로 확인하세요.

  [storage]
    mode             csv  : CSV 파일만 (기본값)
                     db   : DB 만
                     both : CSV 와 DB 모두 (DB 도입 초기에 권장 - CSV 가 백업 역할)
    save_interval_sec 저장 주기(초). 화면 갱신과 별개로 장비마다 이 주기에 1건씩 저장 (기본 30)
                     매 분 0초/30초처럼 시각에 맞춰 저장되며,
                     연결 시작 / 연결 끊기 / 프로그램 종료 시점의 값도 저장됩니다.
                       1  → 장비 1대당 하루 최대 86,400행
                       30 → 장비 1대당 하루 최대  2,880행
                       60 → 장비 1대당 하루 최대  1,440행
    save_only_on_change true 면 저장 시점의 값이 직전 저장값과 같을 때 저장하지 않음 (기본 true)
                     → 장비가 켜져 있어도 멈춰 있으면 같은 값이 쌓이지 않음
                     → 값이 늘거나, 리셋으로 줄어들면 저장
                     false 면 값 변화와 관계없이 저장 주기마다 항상 저장
    keepalive_minutes save_only_on_change = true 일 때, 값이 그대로여도 이 시간(분)마다 1건 저장
                     (기본 60, 0 이면 사용 안 함)
                     → 서버에서 "장비가 멈춘 것"과 "PC/프로그램이 꺼진 것"을 구분하는 생존 신호

  [csv]
    folder           CSV 저장 폴더. 비우면 exe 폴더.
                     공유 폴더도 가능. 예) folder = \\FILESERVER\counter_logs

  [db]
    type             sqlite / mysql / mssql / postgresql
    host, port       DB 서버 주소 / 포트 (포트 비우면 기본 포트 사용)
    database         데이터베이스 이름 (미리 만들어 두어야 함)
    user, password   DB 계정 (mssql 은 user 를 비우면 Windows 인증)
    table            저장 테이블 이름 (기본 counter_log)
    auto_create_table  true 면 테이블이 없을 때 자동 생성
    retry_interval_sec DB 연결이 끊겼을 때 재접속 시도 간격(초)
    sqlite_path      sqlite 파일 경로 (type = sqlite 일 때)
    odbc_driver      mssql 용 ODBC 드라이버 이름
    odbc_options     mssql 추가 접속 옵션 (예: TrustServerCertificate=yes)

  ---------------------------------------------------------
  6-3. DB 쪽 준비 (DB 관리자 작업)
  ---------------------------------------------------------
  (1) 데이터베이스와 계정 생성, 수집 PC 에서 DB 서버 포트로 접속 가능하도록 방화벽 허용
  (2) 계정 권한: INSERT (auto_create_table = true 이면 CREATE TABLE 권한도 필요)
  (3) 테이블은 처음 접속할 때 자동으로 만들어집니다. 직접 만들 경우 구조는 아래와 같습니다.

      컬럼          형식                 내용
      -----------   ------------------   ------------------------------
      id            자동 증가 번호        기본 키
      logged_at     DATETIME             수집 일시 (수집 PC 의 시각, 초 단위)
      station       VARCHAR(100)         수집 PC 이름 ([general] station)
      device_name   VARCHAR(100)         카드에 입력한 장비 이름
      port          VARCHAR(50)          COM 포트
      count_value   BIGINT               카운트 값

      MySQL 예)
      CREATE TABLE counter_log (
          id BIGINT AUTO_INCREMENT PRIMARY KEY,
          logged_at DATETIME NOT NULL,
          station VARCHAR(100), device_name VARCHAR(100),
          port VARCHAR(50), count_value BIGINT,
          INDEX ix_logged_at (logged_at)
      ) DEFAULT CHARSET=utf8mb4;

  (4) 서버에서 취합 예 (MySQL 기준: 날짜/PC/장비별 최대 카운트)

      SELECT DATE(logged_at) AS 일자, station, device_name,
             MAX(count_value) AS 최대카운트
      FROM counter_log
      GROUP BY DATE(logged_at), station, device_name;

  ※ 저장 행 수 (장비 1대당 하루)
     - save_only_on_change = false : 86,400 ÷ save_interval_sec  (30초 → 2,880행)
     - save_only_on_change = true  : 가동 시간에만 쌓임 + 정지 중에는 keepalive 1시간당 1건
       예) 30초 저장, 하루 8시간 가동 → 약 960 + 16 = 976행
     데이터가 많으면 save_interval_sec 를 늘리거나, 오래된 데이터를 주기적으로 정리하세요.

  ※ save_only_on_change = true 일 때 조회 방법
     값이 바뀔 때만 행이 생기므로, "특정 시각의 카운트"는
     그 시각 이전의 가장 마지막 행 값입니다. (그 사이 값은 변하지 않았다는 뜻)

      MySQL 예) 2026-10-01 12:00 시점의 장비별 카운트
      SELECT t.station, t.device_name, t.count_value, t.logged_at
      FROM counter_log t
      JOIN (SELECT station, device_name, MAX(logged_at) AS last_at
            FROM counter_log
            WHERE logged_at <= '2026-10-01 12:00:00'
            GROUP BY station, device_name) m
        ON t.station = m.station AND t.device_name = m.device_name
       AND t.logged_at = m.last_at;

     마지막 행 시각이 keepalive_minutes 보다 오래되었다면
     그 PC 의 프로그램이 꺼져 있거나 DB 연결이 끊긴 상태로 볼 수 있습니다.

  ---------------------------------------------------------
  6-4. DB 연결이 끊겼을 때
  ---------------------------------------------------------
  - 수집은 멈추지 않고 계속됩니다. (저장은 별도 스레드에서 처리)
  - 저장하지 못한 데이터는 exe 폴더의 db_pending.csv 에 임시 보관됩니다.
  - retry_interval_sec 마다 재접속을 시도하고, 연결되면 보관된 데이터를
    DB 에 자동 전송한 뒤 db_pending.csv 를 삭제합니다.
    (프로그램을 껐다 켜도 보관 데이터는 유지되어 다음 연결 때 전송됨)
  - 하단 상태바에 현재 저장 상태가 표시됩니다.
      회색  "저장: CSV · DB(mysql) 연결됨"          정상
      빨강  "저장: DB(mysql) 오류: ... · 미전송 120건"  DB 연결 실패
    오른쪽 끝에는 이 PC 의 station 이름이 표시됩니다.


  ---------------------------------------------------------
  6-5. 카운터 레지스터 확인 (modbus_check.py)
  ---------------------------------------------------------
  카운터 화면의 숫자와 프로그램 숫자가 다를 때, 실제 레지스터 값을 확인하는 도구입니다.
  (Python 이 설치된 PC 에서 실행. counter_app 은 해당 포트 [연결 끊기] 후 실행)

      python modbus_check.py              ← COM 포트 목록
      python modbus_check.py COM3         ← COM3 카운터의 레지스터 값 표시

  Input Register(1000~1011)와 Holding Register(0~11) 값을 읽고,
  각 주소부터 2워드를 low_first / high_first 두 가지로 합친 값을 보여줍니다.
  카운터 앞면에 표시된 현재 숫자와 같은 값을 찾아서
    - 그 표의 종류      → register_type (Input = input, Holding = holding)
    - 그 줄의 '주소'    → pv_address
    - 같은 값이 있는 열 → word_order
  로 settings.ini [modbus] 를 맞춘 뒤 프로그램을 다시 시작하세요.

  예) Holding 0 의 high_first 값이 -1,147,142,131, low_first 값이 900,000 인 경우
      → Holding 0~1 은 PS2 설정값(900,000)이고 워드 순서는 low_first.
        현재값은 Input 1003 (301004) 에 있음.

7. 동작 방식 참고
--------------------------------------------------------------------------------
  - 통신 설정: 9600 bps, Even, Data 8, Stop 1, Slave ID 1 (CT 시리즈 기본값, settings.ini [modbus])
  - 1초마다(poll_interval_ms) Input Register 301004~301005 (현재값, 32비트)를 읽어 화면에 표시
  - 저장은 30초 단위(save_interval_sec)로, 값이 바뀌었을 때만 CSV / DB 에 기록
    (정지 중에는 1시간마다 생존 신호 1건. 연결 시작/끊기/종료 시점 값도 기록) (6장)
  - [0 리셋]: Coil 1 (reset_coil_address) 에 ON 을 보내 카운터를 0 으로 초기화 (연결 중에만 가능)
  - 하나의 COM 포트는 카드 하나만 사용할 수 있습니다.
  - 설정 파일과 CSV 는 항상 exe 가 있는 폴더에 저장됩니다. (CSV 폴더는 변경 가능)
    (자동 실행 시 작업 폴더가 달라도 동일)
  - 설정은 카드 추가/삭제, 연결/해제 할 때마다 즉시 저장됩니다.
    정전이나 강제 재부팅 후에도 마지막 상태로 복구됩니다.
  - 장비 통신은 카드마다 별도 스레드에서 처리되어, 한 장비가 응답하지 않아도
    화면이나 다른 장비 수집이 멈추지 않습니다.

8. 문제 해결
--------------------------------------------------------------------------------
  증상: 부팅 후 카드가 "연결 실패"
    → USB 장치 인식 전에 실행됨. 방법 B 의 지연 시간을 1분으로 늘리거나
      [▶ 연결 시작]을 눌러 다시 연결
    → COM 번호가 바뀌었는지 확인 (4-(5) 참고)

  증상: "응답 오류" 배지 (연결은 됐지만 값이 안 들어옴)
    → 카운터의 통신 설정(9600/Even/8/1, 국번 1), RS485 배선(A/B) 확인
    → settings.ini [modbus] 값이 카운터 설정과 같은지 확인

  증상: 카운트가 음수나 수십억 같은 엉뚱한 숫자로 표시됨
    → 레지스터 주소나 워드 순서가 맞지 않는 경우. 6-5 의 modbus_check.py 로 확인

  증상: 장치 관리자에 "포트(COM & LPT)"가 없고 "기타 장치 > USB Serial Port" 에 ⚠ 표시
    → USB-시리얼 변환기의 가상 COM 포트(VCP) 드라이버 미설치.
      오토닉스 SCM-US48I 드라이버(또는 FTDI VCP 드라이버) 설치 후 USB 다시 연결.
      그래도 없으면 장치 관리자 > USB Serial Converter > 속성 > 고급 > "Load VCP" 체크

  증상: 프로그램이 2개 실행됨 / 한쪽이 연결 실패
    → 방법 A 와 방법 B 를 동시에 설정했는지 확인하고 하나만 남김

  증상: 며칠 뒤 프로그램이 저절로 꺼짐
    → 작업 스케줄러 [설정] 탭의 "다음 시간 이상 작업이 실행되면 중지" 해제 (5-3 g)

  증상: 자동 실행은 되는데 창이 보이지 않음
    → 작업 스케줄러 [일반] 탭을 "사용자가 로그온할 때만 실행"으로 변경

  증상: 설정이 매번 초기화됨 / CSV가 생기지 않음
    → exe 폴더에 쓰기 권한이 있는지 확인 (Program Files 아래에 두지 말 것)
    → 하단 상태바에 "설정 저장 실패" / "CSV 저장 실패" 메시지가 있는지 확인

  증상: 하단 상태바에 "DB 드라이버가 설치되어 있지 않습니다"
    → 해당 DB 드라이버를 설치한 뒤 exe 를 다시 빌드 (2장 (1), 3장)

  증상: 하단 상태바에 "DB(...) 오류: ... Connection refused / timed out"
    → host / port 확인, DB 서버 방화벽에서 포트 허용 여부 확인
    → 연결이 복구되면 미전송 데이터는 자동 전송되므로 따로 조치할 필요 없음

  증상: "Access denied" / "Login failed" / "authentication failed"
    → user / password 확인, DB 계정에 수집 PC 에서의 접속 권한이 있는지 확인

  증상: MS-SQL 에서 "Data source name not found" / "드라이버를 찾을 수 없음"
    → ODBC Driver 17 for SQL Server 설치 또는 odbc_driver = SQL Server 로 변경

  증상: MS-SQL 에서 "SSL" / "certificate" 관련 오류
    → odbc_options = TrustServerCertificate=yes 추가

  증상: 하단 상태바에 "설정 오류: ..."
    → settings.ini 의 해당 항목 값을 확인 (잘못된 값은 기본값으로 동작 중)

  증상: exe 실행 시 "Windows의 PC 보호" 파란 창
    → "추가 정보" → "실행" 클릭 (직접 빌드한 exe라 서명이 없어서 나오는 경고)
